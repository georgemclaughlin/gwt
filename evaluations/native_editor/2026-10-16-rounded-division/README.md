# Explicit rounded-division checkpoint

The native step `divide a by b rounded to 2 places using half_even into result`
makes the precision policy visible in executable source. Five modes operate on
an exact rational quotient; ordinary `/` remains exact-only. See the
[semantics](../../../docs/native-rounded-division.md) and
[quoted-unit-price example](../../../examples/native_rounded_division/README.md).

## Arithmetic, language, and evidence checks

- [Rust results](rust-checks.json): **356 tests** and warning-free Clippy on
  **1.85.0** and **1.96.0**, in development mode. Seven new groups cover all
  policies/signs/ties, recurring quotients, invalid forms/contracts, aliases and
  copies, traversal and example locations, extreme scales/digit overflow,
  budgets/failures before writes, evidence, replay, generated scenarios, and
  formatting. The public example has eight passing scenarios/expectations.
- The [630-case fixture](../../../crates/gwt-core/tests/fixtures/rounded_division.json)
  is independently generated by [Python decimal arithmetic](../rounded_division_oracle.py)
  with precision 1600 and explicit quantization modes. Reproduction matches its
  bytes. These bounded inputs include both signs, negative denominators,
  recurring values, and midpoint policies; this is not exhaustive arithmetic proof.
- [Actual policy review](policy-complete/qualification.json) captures and replays
  **54 inputs** and compares `half_even` with `half_away_from_zero`. Independent
  decimal expectations predict **four changed outcomes/states**. All 54 cases
  compare without baseline mismatches or unavailable entries. Nine zero-unit
  requests fail the same domain assertion on both sides; they are retained in
  `candidateFailed`, not described as nine regressions. Source/evidence changes
  remain visible for all cases. [JSON](policy-complete/review.json) and
  [offline HTML](policy-complete/review.html) are retained; the unchanged renderer
  was not requalified in a browser and no human approval is claimed.
- [Python checks](python-tests.log): **627 tests pass**. All **72 examples**
  format; top-level checks and reference order/tour executions pass. The new
  example is explicitly native-only; its [Python validation rejection](python-validation.json)
  is retained. Five JavaScript unit tests, syntax checks, Rust formatting, and
  diff checks pass; see [final checks](final-checks.json).

## Compatibility and source adaptation

`divide` is now a reserved built-in verb. An actual case using an old custom
behavior named `divide` successfully replays on the retained old executable,
but [migration to the new engine](policy-complete/reserved-verb-migration.json)
reports `candidate_unavailable` with `behavior_name`. Original bytes remain
unchanged, and the proposal is unapproved. The harness's first run incorrectly
expected exit zero for this explicit refusal; the corrected expected-exit check
passes. Earlier runs remain in `policy/` and `policy-final/`.

A separately renamed helper is captured on the old engine and then
[migrated](policy-complete/renamed-migration.json) with complete observation
preservation. Its original is unchanged and candidate replay verifies. This
qualifies the documented rename-before-migration path without silently rewriting
historical cases.

## Reproduce

```sh
cargo test --test rounded_division --locked
python evaluations/native_editor/rounded_division_oracle.py
python evaluations/native_editor/qualify_rounded_division.py \
  --native /path/to/new/gwt-native \
  --previous-engine /path/to/previous/gwt-native \
  --output /tmp/gwt-rounded-division
```

The qualifier requires a fresh output directory. [Source hashes](source-hashes.json)
identify this checkpoint. The full goal remains active: broader language/tooling,
production qualification, and comparative human evidence remain open. No external
pilot or public release occurred.
