# Explicit CLI execution limits

This checkpoint exposes the existing host execution budgets through a shared
`--limits FILE.json` option on native run, profile, capture, test, and validate.
The [guide](../../../docs/native-execution-limits.md) specifies file validation,
command placement, operating limits, and the separate case-profile restriction.
No language syntax or execution semantics changed. The test-command envelope
adds a `limits` field; ordinary run/case payload shapes remain unchanged.

## Resource regression rehearsal

[Workflow qualification](workflow/qualification.json), generated by
[qualify_cli_limits.py](../qualify_cli_limits.py), uses a copied allocation
program and a deliberately inefficient candidate. The candidate repeats an
already-established nonnegative-remainder assertion ten times in its selection
loop. Public example policy source is unchanged.

Both fixtures format, check, and pass all eleven embedded scenarios under the
chosen limits. An eight-recipient equal-weight input with seven cents independently
expects seven one-cent shares and a final zero share. Under default limits both
versions satisfy that expectation with identical complete output and state.

Under the selected budget of 10,000 steps and 262,144 evidence bytes, the baseline
succeeds with 254,632 event bytes. The candidate retains 262,085 bytes before
`evidence_limit` refusal. Both observations are captured with exactly the selected
limits and replay successfully. The one-case review reports one changed outcome,
one failed candidate, zero unavailable entries, and zero baseline mismatches.
The review is unapproved. Its generated HTML was not interactively inspected.

This intentionally shows a coverage gap: small embedded scenarios can pass while
a representative request exceeds the operating budget. Keep both kinds of
validation. Setting the step budget to zero also fails all eleven scenarios,
retains each diagnostic, and produces the requested failure HTML without turning
resource exhaustion into an expected domain failure.

All 57 retained cases from the profiling checkpoint migrate to the new packaged
engine with complete observation preservation. Original bytes remain unchanged,
all migrated candidates replay, and proposals remain unapproved. Individual
migration and candidate artifacts are retained under `workflow/`.

## Remaining work

Explicit settings enable reproducible operating-budget checks; they do not solve
the allocation algorithm's larger-input costs. There is no resource-expectation
language syntax, deadline/cancellation support, or total-memory cap. Captured
case budgets remain restricted to the existing default profile. Broader boundary
authoring, production qualification, and demonstrated human benefit remain open.
