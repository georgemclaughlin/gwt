Before you begin

Run The Walkthrough From A Checkout

GWT currently requires Python 3.11 or newer. Clone the repository and run the examples from its root. Module invocation works without installation; an editable install also provides the shorter gwt command. 

git clone https://github.com/georgemclaughlin/gwt.git
cd gwt

python -m gwtlang version --json

# Optional: install the shorter `gwt` command.
python -m pip install -e .

Step 1

Start With State, Action, And Assertion

A GWT file is executable. This smallest program creates one value, prints it, and checks that it has the expected value. 

PROGRAM hello

GIVEN greeting is "hello world"

WHEN print greeting

THEN greeting == "hello world"

Run the checked-in copy:

python -m gwtlang run examples/hello.gwt --json

GIVEN creates state, WHEN executes a step, and THEN asserts the result. The JSON payload includes the final state and any printed output.

Step 2

Add Fields And Reusable Behavior

Dot paths let you build nested state directly. A block-form WHEN defines reusable behavior; a single-line WHEN runs it. 

PROGRAM bank

GIVEN account.balance is 100
AND account.status is "open"

WHEN withdraw <amount> from <account>
  REQUIRE account.status == "open"
  AND account.balance >= amount
  subtract amount from account.balance

WHEN withdraw 30 from account

THEN account.balance == 70
AND account.status == "open"

The signature names the behavior in readable words and marks parameters with angle brackets. Inside the behavior body, use the bare parameter names.

Step 3

Group Related State Into A Record

When values belong together, use record-shaped setup and assertions instead of setting every path separately. 

PROGRAM records

WHEN withdraw <amount> from <account>
  REQUIRE account.status == "open"
  AND account.balance >= amount
  subtract amount from account.balance

GIVEN account is
  balance: 100
  status: "open"
  owner:
    name: "Ada"

WHEN withdraw 30 from account

THEN account is
  balance: 70
  status: "open"
  owner:
    name: "Ada"

Record-shaped assertions keep examples readable as the state grows.

Step 4

Name The Shape With A Record Contract

RECORD declares the expected shape of state that behavior reads or writes. The checker and runtime use it to catch missing fields, unknown fields, and wrong value types. 

PROGRAM typed bank

RECORD Account
  balance: number
  status: "open" | "closed"
  owner:
    name: text

WHEN withdraw <amount> from <account>
  GIVEN account is Account
  REQUIRE account.status == "open"
  AND account.balance >= amount
  subtract amount from account.balance

GIVEN account is Account
  balance: 100
  status: "open"
  owner:
    name: "Ada"

WHEN withdraw 30 from account

THEN account.balance == 70

Contracts are not classes or methods. They describe the data shape that executable behavior depends on.

Step 5

Add Scenarios As Regression Coverage

SCENARIO starts an independent run with fresh state. BACKGROUND provides setup shared by every scenario. 

PROGRAM bank scenarios

WHEN withdraw <amount> from <account>
  REQUIRE account.status == "open"
  AND account.balance >= amount + fee
  subtract amount + fee from account.balance

BACKGROUND
GIVEN account.status is "open"
AND fee is 3

SCENARIO successful withdrawal
GIVEN account.balance is 100
WHEN withdraw 30 from account
THEN account.balance == 67
AND account.status == "open"

SCENARIO smaller withdrawal
GIVEN account.balance is 50
WHEN withdraw 10 from account
THEN account.balance == 37
AND account.status == "open"

Run the checked-in scenario example:

python -m gwtlang test examples/scenarios.gwt

This is the spec-as-code loop: examples are readable enough to review and precise enough to run in CI.

Step 6

Expose A Named Request

A REQUEST is the public entry point a host application can call. Its body declares caller input, request-local setup, execution steps, output shape, and optional postconditions. 

PROGRAM cart pricing

RECORD Cart
  subtotal: number
  shipping: number
  total: number

REQUEST price cart
  GIVEN cart is Cart

  WHEN price cart

  OUTPUT cart is Cart

  THEN cart.total >= cart.subtotal

WHEN price <cart>
  GIVEN cart is Cart
  IF cart.subtotal >= 100
    set cart.shipping to 0
  ELSE
    set cart.shipping to 8
  set cart.total to cart.subtotal + cart.shipping

A GWT request file can provide input state, invoke the public request, and make assertions about the result. 

GIVEN cart is Cart
  subtotal: 84
  shipping: 0
  total: 0

REQUEST price cart

THEN cart.total == 92
python -m gwtlang run pricing.gwt --input request.gwt --json

Save the program as pricing.gwt and the request block as request.gwt before running that command. Request files do not redeclare the program: the program owns records and behavior, while the request file supplies state and calls the named request.

Step 7

Call The Same Request With JSON

Host applications usually send JSON instead of a GWT request file. The same REQUEST contract validates that input before behavior runs. 

{
  "cart": {
    "subtotal": 84,
    "shipping": 0,
    "total": 0
  }
}
python -m gwtlang run pricing.gwt \
  --json-input request.json \
  --request "price cart" \
  --json

The stable JSON envelope puts declared outputs under result and keeps the complete final state under state. The excerpt below focuses on those two fields; the complete payload also reports the source file, request file, printed output, and scenario metadata. 

{
  "ok": true,
  "result": {
    "cart": {
      "subtotal": 84,
      "shipping": 8,
      "total": 92
    }
  },
  "state": {
    "cart": {
      "subtotal": 84,
      "shipping": 8,
      "total": 92
    }
  }
}

Step 8

Validate, Project, And Capture The Program

The same checked source drives local validation, generated host contracts, and review evidence. No second step-definition or handwritten API model becomes the real implementation. 

python -m gwtlang validate pricing.gwt

python -m gwtlang schema pricing.gwt \
  --output pricing.schema.json

python -m gwtlang openapi pricing.gwt \
  --output openapi.json

Capture one JSON request as an integrity-checked Execution Case, then build a self-contained local review page that verifies the case still replays against the program. 

python -m gwtlang capture pricing.gwt \
  --json-input request.json \
  --request "price cart" \
  --output price-cart.execution-case.json

python -m gwtlang workbench \
  price-cart.execution-case.json \
  --program pricing.gwt \
  --output price-cart-review.html

For repeated old/new review, group named Execution Cases with gwt corpus create, then pass the corpus to gwt compare or gwt workbench.
