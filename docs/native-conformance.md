# Native feature and evidence matrix

This matrix supports the [native draft specification](spec/native-draft.md) and
the [full project goal](project-goal.md). A passing refund
policy is not evidence of complete language support. Native behavior follows
the experimental [semantic decisions](native-semantics.md), introduced in
[the execution-model guide](native-execution-model.md). Unsupported Python forms
require explicit design decisions; the matrix does not commit the native language
to copying them all. Completing the goal still requires a coherent language,
migration coverage, and representative human evidence.

The [repository example audit](../evaluations/native_validation/2026-10-16-example-audit/README.md)
records actual coverage across 75 source files: 46 validate, twenty fail static
checking, two modules have no entry scenarios, one entry has three arithmetic
failures, and six Python request files require paired rules. These are file
counts, not independent language defects. The
[feature-flag adaptation](native-domain-literals.md) demonstrates explicit domain
contracts and literals with 6,272 independently specified inputs; it does not
make the remaining examples conformant.

Rust test paths are relative to [`crates/gwt-core`](../crates/gwt-core/README.md).
The refund probes are independently specified in
[`evaluations/maintenance/manifest.json`](../evaluations/maintenance/manifest.json).
The tests read that acceptance corpus directly; expected results are not
generated by the native engine or the Python interpreter.

The invoice fixture is also checked/formatted/scenario-tested by the existing
Python toolchain, but native expected totals include arithmetic beyond Python's
default decimal precision. Intentional numeric differences are assessed against
independent expected values. None of these checks establishes human benefit,
production qualification, or full v0.2 compatibility.

The reservation example validates the shared syntax with Python as well. Native
collection aliasing, traversal guards, exact arithmetic, and budgets are tested
against explicit expectations rather than inherited from Python. Its capture,
replay, and revision-review test changes the exact-stock boundary from `>=` to
`>` and verifies that the reported reserved quantity changes from five to zero.

The delivery fixture adds ten table-driven scenarios and 16 independent host
requests around weight boundaries, plus two rejected weights. Its source passes
Python format/validate as a shared-syntax check. Native source locations are
validated against original template lines and table cells, including Unicode,
CRLF, skipped expressions, and failures. Imported examples remain excluded
from entry execution and semantic checking.
